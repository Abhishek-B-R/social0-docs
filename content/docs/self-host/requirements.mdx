## Overview

Self-hosting uses the **open-source Social0 v1** repo ([social0-selfhost](https://github.com/Abhishek-B-R/social0-selfhost)), not the closed hosted product. You need Postgres, Upstash Redis (REST), Cloudflare R2 for media, a public HTTPS URL, and outbound HTTPS to social platforms. Scheduling uses a Cloudflare Worker — even when the app runs on a VPS or in Docker.

## Cost checklist

| Need | Free-tier friendly? | Notes |
|------|---------------------|-------|
| Postgres | Yes | Neon, Supabase, or similar free tiers |
| Upstash Redis REST | Yes | Free database is enough for personal/small use |
| Cloudflare R2 | Mostly | Free allowance; pay if you exceed storage/egress |
| Cloudflare Workers (full app) | No (usually) | **Workers Paid ~$5/mo** for the full ~4 MiB gzip app Worker |
| Cloudflare Workers (cron only) | Yes | Free tier works if the app is on Docker/Node elsewhere |
| Domain | Your choice | Required for production OAuth |

You are not required to pay for Postgres or Redis to get started. The predictable bill for the preferred all-on-Cloudflare path is **Workers Paid (~$5/month)**.

## Compute

| Resource | Minimum | Notes |
|----------|---------|-------|
| CPU | 1 vCPU | Only if you run Node/Docker yourself |
| RAM | 1–2 GB | Node standalone or local dev; Workers path has no app RAM you manage |
| Disk | 5 GB+ | Mostly Postgres/Docker layers; media lives in R2 |

On the **Cloudflare Workers** path you do not provision app servers — Cloudflare runs the Worker. You still attach managed Postgres and Upstash Redis.

## Required services

### Postgres

Any Postgres 14+ host. Local dev uses `docker compose` (`postgresql://social0:social0@localhost:5432/social0`).

Production: Neon, Supabase, Railway Postgres, RDS, or self-managed. Set `DATABASE_URL`.

### Upstash Redis (REST)

Sessions and rate limits use **Upstash Redis REST** (`UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN`). A free Upstash database is fine for small deployments.

The optional `redis` service in `docker-compose.yml` is for local experiments; production expects Upstash REST.

### Cloudflare R2

Media uploads need R2. There is no durable local filesystem path for the Workers deploy. See [Object storage](/docs/self-host/object-storage).

### Cloudflare Worker (cron)

Scheduled posts are published by `scheduler/cloudflare-worker`, which calls your app every ~5 minutes with `CRON_SECRET`. Cloudflare **Free** is enough for cron-only. The full app Worker needs **Workers Paid** (~$5/mo) unless you trim the build for Free.

## Network

### Inbound

- Stable **HTTPS** URL in production
- `NEXT_PUBLIC_APP_URL` and `BETTER_AUTH_URL` match that URL
- OAuth redirect URIs in each platform console match your domain

### Outbound

App and cron Worker need HTTPS to social APIs, Upstash, Postgres (or Hyperdrive), R2, and Resend (if used).

### Ports

| Port | Use |
|------|-----|
| **3000** | Default Node / Docker app port |
| **5432** | Postgres (local compose) |
| **6379** | Optional local Redis (compose) |

Behind a reverse proxy, terminate TLS at the proxy and forward to `:3000`. See [Reverse proxy](/docs/self-host/reverse-proxy).

## Domain

- **Cloudflare path:** domain on Cloudflare; set `APP_DOMAIN` in `.env.self-host`
- **Other hosts:** DNS to your server or tunnel; set `NEXT_PUBLIC_APP_URL` and `BETTER_AUTH_URL`

Local: `http://localhost:3000` (or `https://localhost:3000` for Meta OAuth — [Development](/docs/self-host/development)).

## Cloudflare Workers Paid vs Free

| Plan | App Worker | Cron Worker |
|------|------------|-------------|
| **Workers Paid** (~$5/mo) | Full Social0 v1 build (~4 MiB gzip) | Included |
| **Workers Free** | Too large unless you trim platforms | Cron-only works |

Trim guide: [workers-free-trim-platforms.md](https://github.com/Abhishek-B-R/social0-selfhost/blob/main/docs/prompts/workers-free-trim-platforms.md).

## Checklist before deploy

- [ ] Cloned [social0-selfhost](https://github.com/Abhishek-B-R/social0-selfhost) (open v1 edition)
- [ ] Postgres URL ready (`npm run db:migrate`)
- [ ] Upstash Redis REST URL + token
- [ ] R2 bucket + API token + public URL
- [ ] `BETTER_AUTH_SECRET`, `ENCRYPTION_KEY`, `CRON_SECRET` (≥32 chars; self-host script can generate)
- [ ] Google OAuth and/or Resend for sign-in
- [ ] Public HTTPS URL configured
- [ ] Cron Worker deployed with matching `CRON_SECRET` and app URL
- [ ] `BILLING_ENABLED=false` if you want unlimited self-host limits without SaaS billing
